# Discovery sound, version x

The onAdvertRecv override records whether the full public key was already in Contacts before delegating to the existing signature-validated advert processing path. It forwards first-discovery information only to the UI, leaving BLE callback semantics and lazy contact persistence unchanged. The UI suppresses repeat sound events while the node is in Heard. Existing saved contacts and self/duplicate/invalid adverts do not sound.

The discovery tone uses the existing Sound/Volume controls with no display-on predicate. Toast does not wake the display. UI tones now use a bounded FreeRTOS queue and one speaker worker; the main loop never waits for playback. Tone installation failure does not uninstall another audio owner. The worker touches I2S only, not radio/SPI/SD.

Validation: source review covers existing/new saved contacts, unsaved repeated discovery, and muted/zero-volume conditions. Physical speaker preview and build results are recorded after installation. A new independent node advert may not arrive during the test window; preview is not proof of an actual new-node event.

Physical validation: version x application write hash verified. The user heard both one-shot ding previews, with display=1 and display=0; Sound=1 and Volume=6. No synthetic contacts or radio packets were generated by preview. First real new-node sound remains dependent on a valid new advert arriving.
